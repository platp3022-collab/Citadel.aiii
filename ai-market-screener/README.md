# AI Market Screener & Analyst Bot

Скринер рынка: тянет дневные свечи, считает индикаторы локально в pandas, отдаёт
сжатый JSON-снимок в Claude API под жёстким системным промптом и JSON-схемой, и
рендерит из ответа готовый торговый план в Markdown.

```
Data Ingestion  ->  Technical Processing  ->  LLM Analysis  ->  Output
 yfinance/ccxt       pandas (EMA/SMA/RSI/       Claude API      Markdown + JSON
 дневные OHLCV        ATR/RVOL/S&R)          (JSON Schema)      в reports/
```

Разделение обязанностей жёсткое: **вся арифметика в pandas, только суждение — в
модели**. Модель не видит сырых свечей и ничего не вычисляет, поэтому цифры в
отчёте всегда воспроизводимы и проверяемы.

> Не является инвестиционной рекомендацией. Инструмент фильтрации информации.

## Три способа запустить

### 0. Одна HTML-страница — без Python вообще

`screener.html` — самодостаточный файл. Скачайте и откройте двойным кликом:
индикаторы считаются на JavaScript прямо в браузере, запрос уходит в Claude
напрямую со страницы. Ни установки, ни сервера, ни зависимостей.

Ключ вводится один раз и хранится в localStorage браузера. Открывать нужно
**с диска** (`file://`) — на чужом сайте политика безопасности заблокирует
запросы к бирже и к API.

Два источника данных:

| Вкладка | Что берёт | Как |
|---|---|---|
| **Крипта · Binance** | Дневные свечи по парам вида `BTC/USDT` | Автоматически, публичный API биржи открыт для браузера |
| **Свои данные · CSV** | Что угодно, включая акции | Вставить выгрузку с колонками `ticker,date,open,high,low,close,volume` |

Акции автоматически не подтягиваются: Yahoo Finance и брокеры запрещают
запросы со страниц (CORS). Для них — вкладка CSV: выгрузка из TradingView,
Investing.com или терминала подойдёт как есть.

Математика в `screener.html` — построчный порт `main.py`. Совпадение проверено
автоматически: обе реализации считаются на одних данных, все 165 значений
снимка сходятся до последнего знака на пяти сценариях, включая короткую историю.

### 1. В один клик — проще всего

Скачайте папку проекта и запустите:

- **Windows** — двойной клик по `run.bat`
- **macOS / Linux** — двойной клик по `run.sh` (или `chmod +x run.sh && ./run.sh`)

Скрипт сам создаст виртуальное окружение, поставит зависимости и откроет
приложение в браузере. Первый запуск занимает пару минут, дальше — секунды.
Ключ API можно вставить прямо на странице, он сохранится в `.env`.

Нужен только установленный Python 3.11+ ([python.org/downloads](https://python.org/downloads),
на Windows обязательно отметьте галочку **Add Python to PATH**).

### 2. Готовый бинарник — без установки Python

Репозиторий сам собирает исполняемые файлы под Windows, macOS и Linux:

1. Откройте вкладку **Actions** в репозитории на GitHub
2. Слева выберите **Build Market Screener executables**
3. **Run workflow** → при желании смените `onefile` на `onedir` → запустить
4. Через 10–15 минут скачайте архив из раздела **Artifacts** внизу страницы прогона

Внутри — `MarketScreener.exe` (или `MarketScreener` для macOS/Linux), `watchlist.txt`
и `.env.example`. Запускается двойным кликом, Python не нужен.

Два режима сборки отличаются компромиссом:

| Режим | Что получится | Старт |
|---|---|---|
| `onefile` | Один файл, ~150–250 МБ | 10–20 сек: распаковывается при каждом запуске |
| `onedir` | Папка с exe внутри | Мгновенный |

Размер большой, потому что внутрь упакованы Python, pandas, numpy и ccxt со
справочником всех бирж. Скачивать нужно один раз.

Каждая сборка проходит smoke-тест: бинарник запускается, поднимает сервер и
отдаёт страницу с формой — иначе прогон падает и артефакт не публикуется.

### 3. Из исходников — если работаете с кодом

```bash
pip install -r requirements.txt
cp .env.example .env      # и вписать ключ

python webapp.py                              # веб-интерфейс
python main.py --tickers AAPL,MSFT --dry-run  # командная строка
```

## Установка вручную

```bash
pip install -r requirements.txt
cp .env.example .env      # и вписать ключ
```

Ключ Anthropic: [console.anthropic.com](https://console.anthropic.com) → Settings
→ API Keys → Create Key. Вставить в `.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

`.env` в `.gitignore` — ключ никогда не попадёт в репозиторий. Переменная
окружения `ANTHROPIC_API_KEY` тоже работает, если `.env` заводить не хочется.

## Запуск

```bash
python main.py --tickers AAPL,MSFT,NVDA,TSLA        # акции и ETF
python main.py --tickers BTC/USDT,ETH/USDT          # крипта (ccxt, binance)
python main.py --tickers-file watchlist.txt         # список из файла
python main.py --tickers AAPL --dry-run             # без вызова API
```

Результат печатается в консоль и сохраняется в `reports/`:

- `plan_YYYY-MM-DD_HHMM.md` — отчёт для чтения
- `plan_YYYY-MM-DD_HHMM.json` — снимок данных + ответ модели (для бэктеста и аудита)

### Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--tickers` / `--tickers-file` | — | Источник списка (обязателен один из двух) |
| `--benchmarks` | `SPY,QQQ,^VIX` | Контекстные инструменты, в watchlist не попадают |
| `--exchange` | `binance` | Биржа ccxt для крипто-пар |
| `--days` | `100` | Окно анализа в барах |
| `--effort` | `high` | `low`/`medium`/`high`/`xhigh`/`max` — глубина рассуждения |
| `--model` | `claude-opus-5` | ID модели |
| `--lang` | `ru` | Язык текста в отчёте (`ru`/`en`) |
| `--out` | `reports/` | Куда складывать отчёты |
| `--no-news` | выкл. | Не тянуть заголовки новостей |
| `--dry-run` | выкл. | Собрать payload, вывести и выйти — API не вызывается |

`--dry-run` — первое, что стоит запустить: видно ровно то, что получит модель,
и это ничего не стоит.

## Что считается локально

| Индикатор | Реализация |
|---|---|
| EMA 20 | `ewm(span=20, adjust=False)` |
| SMA 50 / SMA 200 | `rolling(n).mean()` |
| RSI 14 | сглаживание Уайлдера (`ewm(alpha=1/14)`) |
| ATR 14 | True Range + сглаживание Уайлдера |
| RVOL | объём сегодня / среднее за **предыдущие** 20 сессий |
| Поддержка / сопротивление | свинг-пивоты (окно 3+1+3), кластеризованные с допуском 0.75×ATR |
| Тренд (`ma_stack`) | `bullish` / `bearish` / `mixed` / `insufficient_history` |

**Почему не `pandas_ta`.** Версия 0.3.14b0 до сих пор делает `from numpy import NaN`,
а `numpy.NaN` убрали в numpy 2.0 — библиотека падает на импорте на любой свежей
установке. Здесь стоят numpy 2.4 и pandas 3.0, и всё работает. Если `pandas_ta`
нужен принципиально, придётся пиновать `numpy<2`.

**Про 100 дней.** В ТЗ было «свечи за последние 100 дней», но SMA200 по
определению требует 200 баров. Поэтому загружается 2 года истории, индикаторы
считаются на полном ряду, а окно в 100 баров используется только для сводных
метрик — диапазонов и уровней. Иначе SMA200 всегда была бы `null`.

## Что уходит в модель

Один JSON на прогон. На инструмент — около 30 полей:

```json
{
  "ticker": "AAPL", "asset_class": "equity", "last_bar": "2026-08-15",
  "price": 231.4, "change_1d_pct": 0.82, "change_5d_pct": 2.1, "change_20d_pct": -3.4,
  "ema20": 228.1, "sma50": 224.0, "sma200": 210.5,
  "price_vs_ema20_pct": 1.45, "ma_stack": "bullish",
  "rsi14": 58.2, "rsi14_5d_ago": 49.0,
  "atr14": 4.2, "atr14_pct_of_price": 1.81, "rvol": 1.35,
  "range_20d": {"high": 236.0, "low": 221.4},
  "support_levels": [226.8, 219.5], "resistance_levels": [234.1, 240.0],
  "pct_to_resistance": 1.17, "pct_to_support": -1.99,
  "news": [{"title": "...", "published": "2026-08-15T13:20"}]
}
```

Плюс блок `market_context`: бенчмарки теми же метриками и breadth по корзине
(доля выше SMA50 / SMA200, доля растущих, средний RSI).

`null` означает «не хватило истории» — системный промпт запрещает модели
достраивать такие значения догадкой.

## Что возвращает модель

Ответ ограничен JSON-схемой (`output_config.format`), так что структура
гарантирована на уровне API — парсинг никогда не падает:

- **`macro`** — режим (`risk_on`/`neutral`/`risk_off`), сводка, ключевые риски,
  правила на день
- **`watchlist`** — по строке на инструмент: тренд, score 1–10, bias, сетап, обоснование
- **`avoid_today`** — что не трогаем и почему конкретно
- **`execution_plans`** — триггер, подтверждение, стоп-лосс, цель, R:R, отмена идеи

Markdown собирается локально из этого JSON, а не берётся из ответа модели —
форматирование детерминированное.

### Правила, зашитые в системный промпт

Ключевые ограничения, которые делают вывод проверяемым:

1. Только числа из снимка. Выдумывать цену, уровень, отчётность или новость нельзя.
2. Каждый уровень в ответе — значение из снимка или простая арифметика от него
   (`support - 0.5 * atr14`), с указанием вывода в тексте.
3. Стоп — за уровнем инвалидации и не ближе 1×ATR от входа.
4. R:R не ниже 1.5, иначе сетап не получает план исполнения.
5. Явная рубрика для score 1–10 — оценки сопоставимы между прогонами.
6. В `execution_plans` попадают только инструменты со score ≥ 6, максимум 5 планов.
   Пустой список — допустимый и правильный ответ, когда торговать нечего.
7. RSI не используется изолированно: экстремум в тренде — это продолжение, а не разворот.

## Стоимость и настройка

Модель — `claude-opus-5` ($5 / $25 за млн токенов). Снимок на 10 инструментов —
примерно 4–6k входных токенов, ответ — 1–3k. Системный промпт помечен
`cache_control`, поэтому со второго прогона подряд он читается из кеша по ~10%
цены.

Рычаги, если хочется дешевле:

- `--effort medium` или `low` — заметно меньше токенов размышления; на Opus 5
  низкие уровни работают неожиданно хорошо, начните со сравнения на своей корзине.
- `--model claude-sonnet-5` — примерно вдвое дешевле при близком качестве на
  такой структурированной задаче.
- `--no-news` — минус заголовки из payload.

Включён серверный `fallbacks: "default"`: если классификаторы безопасности
отклонят запрос, API сам переисполнит его на резервной модели вместо пустого
ответа. Если SDK старый и параметра не знает, код это ловит и повторяет запрос
без него — см. `analyse_with_claude`.

## Ограничения

- Только дневной таймфрейм. Внутридневные сетапы отсюда не увидеть.
- Данные Yahoo Finance бесплатные и иногда с пропусками; для боевого
  использования замените `fetch_equity` на платного провайдера.
- Новости — только заголовки, без тел. Модели явно сказано использовать их как
  флаг событийного риска, а не как факты.
- Нет бэктеста. JSON в `reports/` сохраняется именно для того, чтобы его можно
  было добавить позже.
- Модель не знает вашего размера позиции, налогов и доступности шорта.

## Структура

```
ai-market-screener/
├── main.py            # весь пайплайн, разбит на секции 0-6
├── screener.html      # всё в одном HTML-файле, без Python
├── webapp.py          # локальный веб-интерфейс поверх main.py
├── run.bat            # запуск в один клик, Windows
├── run.sh             # запуск в один клик, macOS / Linux
├── spec.html          # эта документация одной страницей, с полным кодом
├── requirements.txt
├── watchlist.txt      # пример списка тикеров
├── .env.example
└── reports/           # вывод (в .gitignore)

.github/workflows/
└── build-exe.yml      # сборка бинарников под Windows / macOS / Linux
```

`main.py` разбит на секции: 0 — конфиг, 1 — загрузка данных, 2 — индикаторы,
3 — сборка снимка, 4 — интеграция с Claude (промпт + схема), 5 — рендер
Markdown, 6 — CLI.
